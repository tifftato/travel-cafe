# Travel Cafe ☕✈️

검색한 도시의 창가 카페에 잠시 머무는 몰입형 웹 애플리케이션입니다. 
공항 전광판에서 도시를 선택 -> 탑승권 발권 애니메이션 -> 해당 도시의 실시간 날씨와 시간대가 반영된 카페 워크스페이스로 이동합니다.
원래 커피를 구현했는데, 어울리지 않아 커피를 제거했습니다.

## 주요 기능

- 실시간 날씨 연동: OpenWeatherMap API로 조회
- 국가별 라디오 스트리밍: `radio-browser-api`를 통해 국가 코드 기반으로 인기 방송국 자동 재생
- 레이어 기반 렌더링: 배경 이미지, 날씨 오버레이, 창틀·테이블 전경을 분리하여 합성
- 현지 시각 표시: 도시별 타임존 데이터를 기반으로 실시간 시계 위젯
- 포모도로 타이머: 카페 워크스페이스 내 플로팅 위젯
- 사용자 설정 유지: 창틀 표시 여부, 음소거, 온도 단위(°C/°F)를 `localStorage`에 저장
- 탑승권 발권 애니메이션: GSAP 타임라인 기반의 발권 · 스탬프 · 카운트다운 연출
- 유효하지 않은 접근 방어: Vue Router 네비게이션 가드로 존재하지 않는 도시 ID 접근 시 전광판으로 리다이렉트

## 기술 스택

| 구분 | 기술 |
| --- | --- |
| 프레임워크 | Vue 3 (Composition API, `<script setup>`) |
| 라우팅 | Vue Router 5 |
| 상태 관리 | Pinia |
| 애니메이션 | GSAP |
| 빌드 도구 | Vite |
| 라디오 API | radio-browser-api |
| 날씨 API | OpenWeatherMap (서버리스 프록시 경유) |
| 배포 | Vercel |

## 트러블슈팅
1. 날씨 API 실패 은폐 문제
날씨 호출에 실패해도 기본값이 표시되어 오류를 전혀 알아채지 못하는 문제가 있었습니다.
에러 발생 시 이전 값을 비우고 콘솔에 실패한 도시와 원인을 기록하고, 화면에도 "날씨를 불러오지 못했습니다"라는 문구를 띄워 문제를 바로 알 수 있게 했습니다.

2. 로컬 서버리스 함수 실행 오류
로컬 환경에서 개발 서버를 돌릴 때 날씨 API 서버 코드가 실행되지 않고 텍스트로 노출되었습니다.
Vite 개발 서버가 해당 폴더의 서버리스 함수를 제대로 처리하지 못하는 것이 원인이었습니다.
로컬 테스트 환경을 'npm run dev' 대신 'vercel dev' 명령어로 변경했습니다.

3. 라디오 자동재생 차단 오인 문제
브라우저의 자동재생 차단을 진짜 오류로 착각해 방송국이 계속 넘어가는 현상이 있었습니다.
이 두 상황을 분리해, 브라우저 정책 차단일 때는 화면에 안내 문구만 띄우도록 바꿨습니다.
실제로 방송 송출에 문제가 있을 때만 다음 라디오 채널로 넘어가게 만들어 비효율을 줄였습니다.

4. 이미지 파일명 불일치와 용량 문제
AI로 만든 이미지들의 파일 이름이 규칙 없이 제각각이라 관리가 무척 어려웠습니다.
스크립트를 돌려 모든 파일명을 소문자로 맞추고 접두사도 짧게 통일했습니다.
투명도가 필요 없는 배경은 PNG에서 JPG로 변환해 전체 용량을 54MB에서 36MB로 덜어냈습니다.

5. 국가별 사물 배치 오류
배경 이미지마다 테이블 높이가 다른데 고정값을 써서 사물이 허공에 뜨는 문제가 생겼습니다.
이미지의 투명 영역을 픽셀 단위로 분석해 실제 테이블의 시작 위치를 정확히 계산했습니다.
도출된 값을 국가별로 따로 저장하고, 비율이 다른 이미지들에는 크롭 보정을 추가해 해결했습니다.

6. 기능 중복 및 UI 혼란 해결
탑승권과 시계 위젯 모두에 도시 변경 기능이 겹쳐 있어 사용자가 헷갈려 했습니다.
탑승권 요소를 과감하게 덜어내고 시계 위젯 하나로 도시 변경 기능을 완전히 통합했습니다.
어색했던 테이블 위 아이콘들도 치우고 우측 하단의 플로팅 위젯으로 재설계해 깔끔함을 더했습니다.

7. 전광판 STATUS 문구 깜빡임 문제
전광판 문구가 5초마다 계속 바뀌어서 화면을 볼 때 너무 산만하다는 피드백을 받았습니다.
화면을 쳐다보는 동안에는 글자가 바뀌지 않도록 반복 타이머를 아예 없애버렸습니다.
대신 전광판 화면에 새로 들어올 때마다 상태값이 랜덤으로 새롭게 뽑히도록 수정했습니다.

8. 완전 투명 위젯의 가독성 저하
투명한 위젯에 흰 글씨만 썼더니 배경이 밝은 낮 화면에서는 글자가 전혀 안 보였습니다.
텍스트 뒤에 짙고 넓은 그림자 효과를 여러 번 겹쳐 바르는 방식을 시도해 보았습니다.
그 결과 배경색이 밝든 어둡든 상관없이 글자가 아주 또렷하게 잘 보이게 되었습니다.

9. 자체 라디오 서버의 잦은 매칭 오류
라디오 방송국을 영어 이름으로 검색하다 보니 서버마다 표기가 달라 오류가 너무 잦았습니다.
결국 직접 만든 프록시 서버를 지우고 공식 패키지 기반으로 로직을 싹 갈아엎었습니다.
'KR', 'FR' 같은 정확한 국가 코드로 찾게 만들었더니 라디오 재생이 훨씬 안정되었습니다.


## 프로젝트 초기 단계 기초 문법 오류
1. 템플릿과 스크립트 문법 혼동
자바스크립트 영역에서 HTML용 콧수염({{ }}) 문법을 쓰다가 에러를 내는 초보적인 실수를 했습니다.
{{ }}는 화면 렌더링에만 쓰고, 스크립트에서는 백틱을 이용한 템플릿 리터럴을 쓰도록 고쳤습니다.
데이터를 다루는 로직들도 화면이 아닌 스크립트의 라이프사이클 안으로 안전하게 분리했습니다.

2. v-for 스코프 이탈 오류
v-for 반복문 바깥에서 반복 변수인 city에 접근하려다 정의되지 않았다는 에러를 겪었습니다.
반복문으로 만든 변수는 해당 태그와 그 안쪽 자식 요소에서만 쓸 수 있다는 걸 배웠습니다.
여기저기 흩어져 있던 요소들을 하나의 큼직한 단위로 묶어 변수 접근 범위를 맞춰주었습니다.

3. 라우터 인스턴스 초기화 누락
Composition API에서 별도 선언 없이 라우터를 쓰려다 객체를 찾을 수 없다는 오류를 만났습니다.
기존 방식과 다르게 최신 문법에서는 라우터 객체를 직접 불러와야 한다는 걸 깨달았습니다.
상단에 useRouter를 임포트하고 라우터 인스턴스를 명시적으로 선언해서 깔끔하게 해결했습니다.

4. 반응형 데이터 업데이트 불일치
일반 변수의 값을 바꿨더니 콘솔에서는 바뀌는데 화면에는 전혀 반영이 안 되었습니다.
화면이 값의 변화를 알아채려면 반드시 데이터를 ref로 감싸서 만들어야 함을 다시 배웠습니다.
변수를 ref로 고치고 .value 속성을 통해 값을 업데이트하도록 훅 안에 넣어 고쳤습니다.

5. RouterLink와 useRouter 혼동
스크립트 안에서 페이지를 넘길 때 템플릿용 태그인 RouterLink를 불러오려다 에러가 났습니다.
단순히 마크업으로 링크를 걸 때는 RouterLink를, 함수 안에서 넘길 때는 useRouter를 써야 했습니다.
이 둘의 용도와 역할을 명확하게 구분해서 상황에 맞는 올바른 방식을 적용할 수 있게 되었습니다.

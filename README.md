# ☕ Travel Café — 세계 도시 카페 워크스페이스

여행지 카페에 앉아 창밖 풍경을 보며 작업하는 느낌을 주는 포모도로 + 앰비언트 웹앱입니다.
Vue 3 + Vite + Pinia + Vue Router로 만들었고, Vercel 배포를 기준으로 설계했습니다.

```
공항 전광판(도시 선택) → 탑승권 발권 애니메이션 → 카페 워크스페이스(작업 화면)
```

## 빠른 시작

```bash
npm install
vercel dev        # 반드시 vercel dev로 실행할 것 (아래 트러블슈팅 참고)
```

> ⚠️ **`npm run dev`(Vite)로 실행하면 `/api/weather` 서버리스 함수가 동작하지 않습니다.**
> Vite 개발 서버는 `api/` 폴더의 함수를 실행하지 못하고 정적 파일 취급을 해서, 날씨 API가 항상 실패합니다.
> 로컬 개발 시에도 `vercel dev`를 쓰거나, 배포된 Vercel URL에서 테스트하세요.

```bash
npm install -g vercel   # 전역 설치(선택) — 안 하면 매번 npx vercel dev로 실행
vercel dev               # 최초 실행 시 로그인/프로젝트 설정 질문에 답하면 됨
```

## 환경 변수

`.env.example`을 복사해 `.env`로 만들고 키를 채워주세요.

```
OPENWEATHER_API_KEY=여기에_발급받은_키
```

- [OpenWeatherMap](https://openweathermap.org/api)에서 무료 발급 (발급 직후 최대 2시간 정도 활성화 대기 시간이 있을 수 있음)
- `VITE_` 접두어를 붙이지 마세요 — 이 키는 브라우저가 아니라 서버리스 함수(`api/weather.js`)에서만 사용합니다
- Vercel에 배포한다면 로컬 `.env`와 별개로 **Vercel 프로젝트 대시보드 → Settings → Environment Variables**에도 등록하고 재배포해야 합니다

라디오는 [`radio-browser-api`](https://www.npmjs.com/package/radio-browser-api) 패키지가 브라우저에서 직접 공개 API를 호출하므로 별도 키가 필요 없습니다.

## 이미지 에셋 규칙

`public/assets/`에 **국가명 기준**(도시 아님)으로 넣습니다. 같은 나라 도시를 추가해도 에셋을 재사용할 수 있습니다.

| 종류 | 규칙 | 확장자 이유 |
| --- | --- | --- |
| 배경 (낮, 필수) | `bg_{country}.jpg` | 투명도 불필요 → JPG로 용량 절감 |
| 배경 (밤, 선택) | `bg_{country}-night.jpg` | 없으면 낮 사진에 CSS 필터(어둡게+블루 톤)로 자동 대체 |
| 창틀+테이블 (낮, 필수) | `frame_{country}.png` | 크로마키 투명 배경 필요 → PNG |
| 창틀+테이블 (밤, 선택) | `frame_{country}-night.png` | 없으면 낮 사진을 밤에도 그대로(필터 없이) 사용 |

## 이스터에그 — 갈리프레이

`TardisFlyby.vue`가 App.vue에 전역으로 떠 있으면서, 대략 1시간에 한 번(45~75분 사이 무작위,
첫 방문 시엔 발견하기 쉽게 1~3분 안에 한 번 먼저 등장) `tardisPaths.js`에 정의된 24가지 경로
중 하나를 무작위로 골라 CSS 3D transform(Web Animations API)으로 화면을 가로질러 날아갑니다.
`prefers-reduced-motion` 환경에서는 아예 뜨지 않습니다.

타디스를 클릭하면 `/boarding/gallifrey`로 이동합니다 — **갈리프레이**는 `hidden: true`로
표시된 히든 도시라 전광판 검색(`journey.js`의 `allCities`)에는 절대 안 나오고, 오직 이 클릭으로만
갈 수 있습니다. 실제 좌표(`lat`/`lng`)가 없어서 `weather.js`가 날씨 API를 호출하지 않고 사용자의
로컬 시간 기준으로 낮/밤만 판단하고, `TravelClock.vue`는 `timezone: 'relative'`를 보고 "타임로드에게
시간은 상대적이니까요" 컨셉으로 사용자의 현재 시간을 그대로 보여줍니다. 라디오는 실제 방송국 대신
`youtubeId`로 지정한 유튜브 영상(기본값: Gallifrey, Our Childhood, Our Home)을 유튜브 IFrame API로
재생합니다 (`radio.js`의 `_loadYoutube`).

⚠️ 참고: `gallifrey-day-frame.png`가 배경(1672×941, 16:9)과 달리 1536×1024(3:2)로 왔습니다.
프레임을 배경 크기에 강제로 리사이즈해서 저장했고(가로 +8.9% / 세로 -8.1% 정도 왜곡), 육안으로는
거의 티가 안 나서 그대로 사용했습니다 — 나중에 올바른 비율의 프레임이 생기면 `frame_gallifrey.png`만
다시 만들면 됩니다.

## 커피 김/물방울 효과 + 냅킨 메모

`hotspots.coffee`가 있는 나라(17개국)는 커피/음료 잔 위에 자동으로 효과가 얹힙니다.

- **`iced: true`가 없으면(기본값)** 잔 위로 김이 피어오릅니다 (`CoffeeEffect.vue`). 서울만 아이스
  아메리카노가 사진에서 명확히 확인돼서 `iced: true`로 설정했고, 나머지는 전부 뜨거운 음료로
  간주했습니다 — 실제로 아이스인 나라가 더 있다면 해당 도시의 `hotspots.coffee.iced: true`만
  추가하면 바로 물방울 효과로 바뀝니다.
- **잔 옆(받침대 자리)을 클릭**하면 `NapkinMemo.vue`가 뜹니다 — 업로드해주신 냅킨 텍스처
  (`public/assets/napkin-texture.jpg`)를 배경으로, 손글씨 폰트(Nanum Pen Script / East Sea
  Dokdo, Google Fonts)로 "오늘 집중할 목표 1가지"를 적을 수 있습니다. 도시별로
  `localStorage`(`travel-cafe:napkin:{cityId}`)에 저장되어 다음 방문 때도 남아있습니다.

`hotspots.coffee`는 기존에 주석으로만 기록해뒀던 좌표(`region`+`point`)를 실제 필드로 승격한
것입니다 — `region`은 잔 전체 범위(김/물방울이 표시될 영역), `point`는 클릭 핫스팟 중심점입니다.

## 날씨 클리핑 — 반전 마스크 방식 (베이크인 국가 전용)

베이크인 국가(오스트리아·호주·브라질·쿠바·체코, `hotspots`가 있는 나라)는 `bg_{country}.jpg` 자체가
소품까지 다 그려진 원본 이미지라서, `frame_{country}.png`를 화면에 또 그리면 완전히 같은 그림이
중복으로 겹쳐질 뿐입니다. 그래서 이 나라들은:

- `frame_{country}.png`를 화면에 렌더링하지 않고(핫스팟 좌표 계산용 기준 엘리먼트로만 DOM에 유지),
- 대신 `frame_{country}.png`의 알파를 반전한 `mask_{country}.png`(창문=흰색/보임, 소품·벽=검정/숨김)를
  만들어서 `WeatherOverlay.vue`의 CSS `mask-image`로 사용합니다.

결과적으로 배경(원본 베이크)이 이중 합성 없이 그대로 보이면서도, 비·눈 같은 날씨 효과는 여전히
창문 모양대로만 정확히 클리핑됩니다. `hotspots`가 없는 기존 나라들은 `bg.jpg`가 랜드마크만 있는
순수 배경이라 지금처럼 `frame.png`를 실제로 그려서 z-index로 클리핑합니다 — 두 방식이 나라별로
자동으로 분기됩니다 (`FrameForeground.vue`의 `isBakedIn` 참고).

반전 마스크 만드는 법:
```bash
convert frame_{country}.png -alpha extract -negate mask_{country}.png
```

**밤 마스크가 없거나(또는 야간 프레임 이미지의 해상도/비율이 다른 나라들과 어긋나는 경우) 자동으로
낮 마스크로 폴백합니다** (`WeatherOverlay.vue`). 낮/밤은 같은 구도(같은 `--seed`)라 창문 위치가
동일하므로 낮 마스크를 밤에 그대로 써도 정확히 맞습니다. 예: 이집트·프랑스·이탈리아는 `-night-frame.png`가
1536×1024(3:2)로 다른 나라(1672×941, 16:9)와 달라서 각각 `mask_egypt-night.png`/`mask_france-night.png`를 아예 만들지
않았고, 밤에도 각 나라의 낮 마스크가 자동으로 쓰입니다.

베트남은 조금 다른 케이스입니다 — 낮/밤 bg·frame 4개 파일이 전부 다른 나라(1672×941, 16:9)와
달리 3:2(1536×1024 안팎)로 일관되게 나왔습니다. `bg`와 `frame`끼리는 서로 크기가 거의 같아서
(1px 오차 수준) 마스크 정합성엔 문제없이 정상 동작합니다 — CSS `mask-size: cover`는 배경 이미지와
마스크 이미지를 각자의 실제 크기 기준으로 독립적으로 계산하므로, 두 이미지의 절대 해상도가 달라도
정렬이 어긋나지 않습니다. 문제가 되는 경우는 프랑스·이집트·이탈리아처럼 **같은 나라의 낮/밤 프레임
끼리** 비율이 어긋나는 경우뿐입니다.

## 낮 ↔ 밤 전환

`weather.js`가 OpenWeatherMap 응답의 일출·일몰 기준(`isNight`)을 계산해서 실시간으로 넘겨줍니다.
그 시점에 **해당 나라의 야간 전용 파일이 있는지 자동으로 확인**해서:

- `bg_{country}-night.jpg` / `frame_{country}-night.png` 둘 다 있으면 → 그 사진을 그대로 사용 (필터 없음)
- 없으면 → 낮 사진에 CSS 필터(어둡게 + 블루 톤)를 입혀서 흉내

즉 나라별로 야간 사진을 준비하는 대로 하나씩 자동 적용되고, 아직 없는 나라는 지금처럼 CSS 필터로
자연스럽게 동작합니다. [`docs/midjourney-prompts.md`](docs/midjourney-prompts.md)의 방법대로 같은
`--seed`로 낮/밤을 뽑으면 구도가 유지되므로, `hotspots` 좌표(라디오·타이머 위치)는 **낮 이미지 기준
하나만 있으면 밤에도 그대로 재사용**됩니다.

18개 도시의 `{country}` 키: `korea`, `italy`, `france`, `usa`, `japan`, `australia`, `turkey`, `austria`, `vietnam`, `cuba`, `brazil`, `czech`, `egypt`, `hongkong`, `portugal`, `spain`, `swiss`, `uk`

나라마다 사진 구도가 달라 테이블이 시작되는 높이가 제각각이라, `src/data/cities.js`의 `tableTopVh` 값에
각 `frame_*.png`를 **알파 채널 분석으로 실측**한 값을 넣어뒀습니다 (아래 트러블슈팅 참고). 이미지를 바꾸면
이 값도 다시 맞춰야 할 수 있습니다.

### 에셋을 "베이크인 + 분리 추출" 방식으로 만드는 법 (합성 이질감 없애기)

> 18개 도시에 바로 쓸 수 있는 완성형 프롬프트는 [`docs/midjourney-prompts.md`](docs/midjourney-prompts.md) 참고.

`bg_*.jpg`와 `frame_*.png`를 따로 생성하면(배경 따로, 창틀 따로) 조명·색온도가 미묘하게 어긋나
"합성한 티"가 날 수 있습니다. 대신 아래 순서로 만들면 **한 장의 사진에서 자연스럽게 뽑아낸** 두 레이어가 됩니다.

1. Midjourney로 창문·랜드마크·테이블·커피/디저트·꽃병·라디오·타이머 소품까지 전부 담긴 **베이크 장면**을
   `--ar 16:9`로 생성 (낮/밤 각각, 같은 구도를 유지하려면 `--sref`로 스타일 고정)
2. 그 이미지에서 유리창(랜드마크가 보이는 부분)만 마스킹해서 오려냄 — 창문살에 가려진 부분은 이 단계에선 빈 칸으로 둠
3. 마스킹한 이미지를 Midjourney의 **Vary(Region)** 기능으로 창문살에 가려졌던 시야를 자연스럽게 복원
4. **Pan/Zoom Out**으로 좌우·상하를 늘려 완전한 16:9 배경 사진 완성 → 이게 `bg_{country}.jpg`
5. 원본 베이크 이미지로 돌아가 이번엔 반대로 창문 안쪽(하늘/랜드마크)을 지우고 창틀·테이블·소품만 투명 PNG로 저장 → 이게 `frame_{country}.png`

### 라디오·타이머를 "그림 속 소품 클릭"으로 인터랙티브하게 만들기

`frame_{country}.png`에 라디오·타이머 소품이 실제로 그려져 있다면, `cities.js`의 `hotspots`에
좌표를 넣어보세요. 컨트롤 종류에 따라 세 가지 방식을 섞어 씁니다.

```js
hotspots: {
  // 타이머: 소품에 빈 화면(디지털 디스플레이)이 있다면 그 사각형 영역에 숫자를 직접 삽입
  timer: { screen: { x: 0.42, y: 0.62, width: 0.16, height: 0.10 } },

  // 라디오: 이름은 빈 표시창에 텍스트로, 재생은 버튼 위 핫스팟, 볼륨은 노브 위 드래그 컨트롤
  radio: {
    display: { x: 0.68, y: 0.58, width: 0.12, height: 0.04 },
    power:   { x: 0.66, y: 0.66 },
    volume:  { x: 0.74, y: 0.66 },
  },
}
```

빈 화면/표시창이 없는 단순한 소품이라면 점 좌표(`{ x, y }`) 하나만 넣어도 됩니다 — 이 경우 클릭하면
근처에 작은 팝오버가 뜨는 예전 방식으로 자동 대체됩니다.

- **타이머 숫자·라디오 이름**: 카드/배경 없이 텍스트만 얹고, `TravelClock`과 같은 고대비
  `text-shadow`로 어떤 배경에서도 읽히게 처리 (`TimerInline.vue`, `RadioInline.vue`)
- **재생/정지 버튼**: 그림 자체는 상태를 못 바꾸니, 클릭 시 CSS 글로우/펄스만으로 "켜짐"을 표현
- **볼륨 노브**: 클릭이 아니라 실제 오디오 노브처럼 **드래그해서 돌리는** 회전형 컨트롤
  (`RotaryKnob.vue`, 포인터 각도를 계산해 0~1 값으로 변환)

`hotspots`를 아예 안 넣거나 일부만(예: 타이머만) 채워도 됩니다 — 커버되지 않은 나머지는 화면
우하단 플로팅 위젯이 자동으로 보완하므로, 나라별·소품별로 하나씩 순차 적용해도 깨지지 않습니다.

> ⚠️ 소품은 가로 0.3~0.7 사이(화면 중앙 근처)에 배치하세요. 세로로 좁은(모바일) 화면일수록
> `object-fit: cover`가 원본 사진의 좌우 가장자리를 잘라내므로, 0.2 이하/0.8 이상에 두면
> 모바일에서 화면 밖으로 잘려나갈 수 있습니다.

## 개발 중 겪은 실수와 수정 기록

실서비스로 이어받아 작업하실 때 같은 실수를 반복하지 않도록, 실제로 발견됐던 버그와 원인·수정 방법을 남겨둡니다.

### 1. 날씨 API 실패가 "성공한 것처럼" 보이던 버그

**증상**: API 키를 넣었는데도 모든 도시의 날씨·기온이 항상 동일하게 나옴.

**원인**: `weather.js`의 에러 처리가 실패 시 이전 값(또는 기본값 20°C·맑음)을 그대로 재사용하도록 되어 있었음.

```js
// 문제가 있던 코드
this.tempC = this.tempC ?? 20   // 실패해도 이미 값이 있으면 그대로 유지
this.condition = 'clear'         // description, isNight는 아예 초기화도 안 함
```

매번 실패해도 겉보기엔 "정상적으로 항상 같은 날씨"가 나와서, 실패 자체를 알아채기 어려웠습니다.

**수정**: 실패 시 값을 확실히 초기화하고, 어떤 도시에서 왜 실패했는지 `console.error`로 남기도록 변경. 화면에도
"⚠️ 날씨를 불러오지 못했습니다"를 명시적으로 표시해서 실패가 숨겨지지 않도록 함.

### 2. `npm run dev`로는 서버리스 함수가 절대 실행되지 않음

**증상**: `.env`에 키를 넣고 `npm run dev`로 테스트했는데 계속 실패. 콘솔에는
`Unexpected token '/', "// GET /ap"... is not valid JSON` 에러.

**원인**: Vite 개발 서버는 `api/` 폴더를 서버리스 함수로 실행하지 않습니다. `/api/weather`를 요청하면
`api/weather.js` **소스 코드 원문**이 그대로 텍스트로 돌아왔고, 그걸 JSON으로 파싱하려다 실패한 것.

**수정**: 로컬 개발도 `vercel dev`로 실행하도록 안내. (Vite와 포트가 겹치므로 `npm run dev`는 꺼두고 실행)

### 3. 라디오 자동재생 차단을 "스트림이 죽었다"고 오해해서 계속 다음 방송국으로 건너뛰던 버그

**증상**: 자동재생 기능 추가 후, 멀쩡한 방송국인데도 카페 진입 시 재생이 안 되고 계속 다음 후보로 넘어감.

**원인**: 브라우저의 자동재생 정책(`NotAllowedError`)과 스트림 자체 오류를 구분하지 않고 둘 다
"재생 실패"로 처리해서 `_tryNextStation()`을 호출했음. 정책 차단은 어떤 방송국을 틀어도 똑같이 막히므로
방송국을 바꿔봤자 의미가 없는데, 계속 다음 방송국을 갈아치우는 낭비가 발생.

**수정**: 에러 원인을 분기 처리. `NotAllowedError`(자동재생 정책)면 조용히 대기하며 위젯에 안내 문구만 띄우고,
그 외(스트림 자체 문제)만 다음 후보로 전환하도록 수정.

### 4. 업로드된 이미지 파일명이 코드 규칙과 안 맞았음

**증상**: `background_USA.png`, `coffee_Italy.png`처럼 파일마다 대소문자·접두어가 제각각.

**원인**: AI로 생성한 이미지 파일명이 사람이 붙인 이름 그대로라 규칙이 없었음.

**수정**: 스크립트로 일괄 소문자 변환 + `background_` → `bg_` 접두어 통일. 추가로 배경 이미지는 투명도가
필요 없다는 걸 이용해 PNG → JPG로 바꿔 54MB → 36MB로 용량도 줄임.

### 5. 나라마다 테이블 위치가 달라서 사물이 창문에 걸치던 문제

**증상**: 모든 나라에 동일한 `28vh` 높이로 사물을 배치했더니, 어떤 나라는 사물이 테이블 위에 자연스럽게
놓이고 어떤 나라는 창문 유리 위에 걸치거나 허공에 뜬 것처럼 보임.

**원인**: `frame_*.png` 사진마다 테이블이 화면의 몇 %를 차지하는지가 실제로는 25%~43%까지 제각각인데,
하나의 고정값을 썼음.

**수정**: 각 `frame_*.png`의 **알파 채널을 행(row) 단위로 분석**해서 "유리창(투명)이 끝나고 벽/테이블(불투명)이
시작되는 지점"을 픽셀 단위로 자동 측정. 프랑스 이미지만 다른 나라와 사진 비율이 달라서(3:2 vs 16:9)
`object-fit: cover` 특성상 발생하는 크롭 비율까지 추가로 보정. 그 결과값을 `cities.js`의 `tableTopVh`에 나라별로
저장. (실제 합성 이미지로 검증 후 반영)

### 6. 기능이 중복돼서 오히려 헷갈리던 UI

**증상 / 판단**: 도시를 바꾸는 방법이 "비행기 티켓 클릭(인라인 드롭다운)"과 새로 만든 "시계 위젯의
다른 도시로 버튼(전광판 이동)" 두 가지로 중복됨. 포모도로도 "테이블 위 폰 아이콘 클릭" 방식이 화면
전체 톤과 안 어울린다는 피드백.

**수정**: 비행기 티켓 컴포넌트를 제거하고 시계 위젯의 버튼으로 도시 전환 기능을 통합. 포모도로+라디오는
테이블 위 폰 아이콘 방식을 버리고 화면 우하단에 항상 떠 있는 플로팅 위젯(`CafeWidget.vue`)으로 재설계.

### 7. 전광판 STATUS가 보고 있는 동안 계속 깜빡이던 문제

**증상**: "FINAL CALL", "BOARDING" 같은 상태를 5초 주기 `setInterval`로 순환시켰더니, 화면을
가만히 보고 있어도 값이 계속 바뀌어 산만함.

**원인**: 요구사항을 "실시간처럼 보이면 좋겠다"로 확대 해석해서 타이머 기반 로테이션을 넣었는데,
실제로는 "도시를 다시 선택하러 돌아왔을 때만" 바뀌길 원했음.

**수정**: 타이머를 제거하고, 컴포넌트가 **마운트될 때 한 번만** 무작위로 상태를 뽑아 고정. 다시 전광판으로
돌아오면(라우트 변경으로 재마운트) 그때만 새로 뽑히도록 변경.

### 8. 완전 투명 위젯의 가독성

**증상 / 요구사항**: 시계 위젯에서 배경 패널을 완전히 없애 달라는 요청 — 배경색이 밝은 나라(예: 한국 낮
배경)와 어두운 나라(예: 야간)를 모두 가려야 해서 단순히 흰 글씨만 쓰면 밝은 배경에서 안 보이는 문제가
예상됨.

**수정**: 배경 패널 대신 다중 레이어 `text-shadow`(진한 그림자 + 넓은 블러)로 어떤 배경 위에서도 읽히는
고대비 텍스트를 구현. 실제 서울 배경 이미지에 합성해 가독성을 확인.

### 9. 자체 라디오 프록시 → 공식 패키지로 교체

처음에는 `radio-browser.info`를 직접 호출하는 Vercel 서버리스 프록시(`api/radio.js`)를 만들었으나,
국가 전체 이름(`"South Korea"` 등) 문자열 매칭이 API 서버마다 표기가 미묘하게 달라 깨지기 쉬웠습니다.
이후 [`radio-browser-api`](https://www.npmjs.com/package/radio-browser-api) 패키지로 교체하면서
ISO 3166-1 alpha-2 국가 코드(`countryCode: 'KR'`)로 검색하도록 바꿔 안정성을 높이고, 서버리스 함수도
하나 줄였습니다 (`api/radio.js` 삭제).
